# 基于 Ticket 与消息的 IT 服务用户画像可行性核查

## 目标

核实六区块用户服务画像的数据可用性。仅现有 PostgreSQL 同步快照、消息及已有 AI 分析；不新增产品功能，不触发同步或外部写入。

## 验收标准

- [x] 只读统计实际覆盖情况，核对源字段与投影差异。
- [x] 区分可直接聚合、需要推导、当前数据无法可靠支持的内容。

## 背景与范围

2026-09-14 使用当前 server 配置的数据库，pg 连接强制 default_transaction_read_only=on 和 statement_timeout。仅输出聚合计数及结构，不输出人员标识、消息正文或凭据；未核实该连接是否代表生产全量数据。

## 方案与决策

| 核查项 | 当前结果 |
| --- | --- |
| Ticket 总量 | 1,912；stale=true 为 1,602。stale 由同步未见记录标记，不等同已删除或业务关闭。 |
| 需求人 | 原始 fields_json 有 1,814 张包含身份 ID 和姓名，128 个不同 id；清洗 requester 非空仅 348。按原始身份 ID 聚合，不按显示文本归人；同应用身份命名空间与消息角色映射仍待验证。 |
| 字段覆盖 | Responsible 1,897；Business line 1,646；创建时间 1,912；关闭时间 1,513；解决方案 384；预计修复日期 61；财务期望解决时间 38；财务是否已解决字段 50。非空不等于业务语义已确认。 |
| 线程 | 1,849 份，history_complete=true 为 1,849；19,001 条消息；frozen 1,650，dirty 0，有 last_error 1。线程独立统计，未成功核实逐 Ticket 连接覆盖。 |
| 消息类型 | text 13,671；post 5,006；file 121；image 51；其余为卡片、合并转发、表情、待办及媒体。图片键及附件引用不是可直接理解的正文。 |
| 新鲜度 | Ticket 最大 synced_at 为 2026-09-13 06:39 UTC；线程最大 last_successful_sync_at 为 2026-09-11 20:03 UTC，最早为 2026-08-31。全局最新时间不能代表每个用户的数据时间。 |
| AI | 非空 ticket_ai 303；shadow_ai 状态 ok 1,847、skipped 47、error 1；ok 不等于人工审核或恢复确认。 |

可直接开发：基于有身份 ID 的工单形成用户概况、历史工单列表、状态/类型/业务线分布、创建关闭时间、已有解决方案与负责人；统计口径限定已有同步记录。

需推导并引用证据：业务场景、当前诉求、已尝试/无效方案、待补信息、相似问题候选、优先行动、沟通提纲、恢复确认及追问线索。需补身份角色解析、时间/否定/更正处理以及有效快照筛选；不视为已有用户画像功能。

当前无法可靠支持：完整组织岗位与资产权限画像、实时阻塞、真实满意度、正式 SLA 违约、稳定沟通偏好、精确客服首响/等待时长、同根因复发率。已有时间戳可以计算观测值，但不足以赋予这些业务含义。

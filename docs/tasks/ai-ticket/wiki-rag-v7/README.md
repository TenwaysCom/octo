# v7：真实精排输入与阈值实验

本轮结论：**保留当前精排输入和0.7阈值，不采用B／C输入改动。** 当前配置在首次新24事件上达到预先约定的验收标准；没有证明新的输入表示带来可采用的收益。业务源码、共用知识、数据库和部署配置均未应用实验改动，原文关联G继续只保留候选。

本轮经用户确认后调用现有SiliconFlow `BAAI/bge-reranker-v2-m3`，共231次HTTP请求，230次成功、1次429，均计入310次上限。限流后停止，检查状态后单次重试成功；原失败记录保留，未自动循环重试。未调用问题提取模型或最终答案模型，未验证生产问答。

## 基线和变量

起点是当前工作区456个server源码文件和当前共用知识5181个文件的冻结副本，**不是v5候选或v6 RG**。固定reader Top20、提取结果、知识／raw、环境筛选、原文选择、每候选2400字符原文预算和最终最多3篇；G、R及v5字段消费优化均关闭。冻结目录为`/tmp/octo-wiki-rag-v7`，原始来源和模型请求正文只存在该隔离目录，不写入报告。

| 组别 | 模型query | 模型document |
| --- | --- | --- |
| A | 原冻结question | 现有title／environments／content JSON，沿用生产链接目标清理 |
| B | 同A | 自然语言标题、已有summary、状态／限制及完整相关正文和适用边界 |
| C | 能核对当前原始提问时，question补充当前票首条原始提问 | 同B；不从目标文章、后续支持答复或期望答案补信息 |

所有组document上限3200字符、query上限2000字符，不截断普通段落或关键限制。B整段边界超限时明确拒绝正文。C可用当前原始提问的旧题为43/77；其他34题不声称测过C，汇总C策略时明确回退B。它只检验本轮准备的当前提问补充方式，没有实现或验证新的语义意图分析器。B同时改变格式、摘要及段落表示，不能将其结果单独归因于summary。

专用BGE实际只发送model、query、documents、top_n、return_documents，**不发送通用精排提示词**。测试库模板已只读冻结：数据库rerank仍写最多3篇，仓库写最多5篇，但专用请求取Top5，不受该模板文字影响。extract模板也有差异；本轮冻结提取结果，不将提示词差异混入实验。不自动同步数据库模板。

## 冻结与独立性

- 旧77题全部作为开发／回归，其中61题有既有期望页，当前reader只召回其中50题；11题召回缺失单列，不能归因精排。
- 首次模型请求前，冻结新24事件和标签：12正例、6个同主题不同诉求的明确错误配对、6个冻结候选内无本次具体问题支持材料的请求。12正例的期望Wiki页均在Top20；6个明确错误配对也均实际在Top20，没有注入未召回页面。
- 新事件按当前票去重；21项由原始raw确认，另3项由留存的当前Ticket输入／提取日志确认，分别对应2223、2238、2237。后者不冒充原始用户逐字提问。零金额上传、Invoice Address区块和新功能请求使用其真实当前材料，没有伪造对照问题。
- “无可用知识”针对本次具体需求／实现／交付依据，不等于全库没有同主题背景。背景或无关页都不足以支持当前问题；未列为gold的页面不自动当错。正例其他候选未逐一穷尽标注，不报告全局precision或所有回答正确率。
- 先用旧题选择，再写入[selection-lock.json](selection-lock.json)，之后才调用新24事件；首次新结果未用于改输入、标签或阈值。候选选择实际为A／0.7，与基线完全相同，新留出相同请求只调用一次。**没有新留出B／C对照收益可宣称。**

证据：[输入和候选冻结](freeze.json)、[案例](cases.json)、[标签](labels.json)、[逐题结果](ranks.csv)。冻结时记录输入哈希／长度和路径；没有把完整客户聊天保存为报告结果。

## 开发结果和选择

以下分母50为当前Top20内有期望页的题；总正例为61，另外11题没有候选资格。

| 配置 | 期望页Top5 | 过0.7的期望页 | 最终目标页正文＋原文 | 6个无答案开发事件被接纳 |
| --- | --- | --- | --- | --- |
| A 现状 | 45/50 | 35/50 | 26/50 | 0/6 |
| B 文章表示 | 47/50 | 34/50 | 24/50 | 3/6 |
| C 当前提问补充策略，含无原文时B回退 | 44/50 | 34/50 | 24/50 | 3/6 |

C实际有当前材料且正例已召回的共同子集为31题：A／B／C的Top5分别26／28／25，过0.7均为21；数量相同也不代表命中的是相同题。完整题号和回退记录见[开发原始汇总](development-summary.json)。

开发集0.1–0.9步长0.1全部比较：

- A降至0.6，正确期望页35→38，但6个无答案事件中2个被接纳；降至0.5则4个被接纳。
- A升至0.8，正确期望页35→33，丢失Q17／V08。
- B／0.7丢失A原本保留的Q17／V08，同时增加H08／H09／H11无答案接纳；C／0.7也有逐题回退。
- B／C提高到0.9可挡住这6个无答案开发事件，但仍丢失A原有正确结果。不能仅凭总体非空数或Top5数量选择改动。

按“不丢基线正确页及原文、拒绝已标错配和无答案”的开发约束，本轮预设网格内唯一满足的配置是**A／0.7**。这不是在新留出集挑选的阈值，也不表示0.7是所有业务的全局最优值。

旧10个明确错配中，当前reader实际只召回N12／N13两项；A／0.7均不接纳，其中N13进入Top5后因低分被拒绝。v5字段扩展引入的Q31／Q32／Q34／H12四项在本轮当前reader中没有召回，**不能据此声称BGE已验证挡住v5新增的四项噪声**。本轮没有做v5扩召回与精排的联合实验。

两项需要分别解释：

- **T02资产原值修改**：目标Wiki排第2，分数约0.6335，被0.7挡住；同题固定资产Ontology约0.8921仍保留。失去目标Wiki页不等于整题没有参考资料，也不能凭单题在新留出后降阈值。
- **T01订单可见性**：正确Wiki排第1、约0.9895，通过精排，但其原文与完整上下文需要3244字符，现有预算2400，因此目标页正文和原文被清空；其他两篇历史材料仍保留。这是原文消费限制，不是精排误删。诊断只统计放大预算时的所需长度，**没有把超限内容送入实际证据**，见[原文预算核对](source-budget-audit.json)。G也不能通过将预算失败改称语言不匹配来绕过限制。

新留出只有24个事件，难负例和无答案各6个，且正例主要由知识可追溯的真实票构造；这是有明确边界的小样本验收，不构成所有线上分布或最终答案质量的保证。

## Vendor Bill原问题的分层结果

同一当前基线、同一真实BGE下：

| 冻结问法 | 调查页进Top20 | 精排表现 | 后续目标页 |
| --- | --- | --- | --- |
| `confirm vendor bill` | 是 | 第1，约0.9777 | 正文770字符＋原文1521字符 |
| `Expected singleton: stock.move()` | 是 | 第1，约0.9897 | 正文726字符＋原文1395字符 |
| `_tw_purchase_original_currency_unit_price` | 是 | 第1，约0.9731 | 正文590字符＋原文1395字符 |
| `供应商账单确认失败`，无keywords扩词 | 否 | 正确页未送进精排 | 精排无法补回 |
| `Bill过账失败`，无keywords扩词 | 否 | 正确页未送进精排 | 精排无法补回 |

这说明此前导出／traceback修复后的当前材料，至少在这三个已知问法下可被真实精排及原文消费。纯中文冻结问法的缺口在召回；本轮没有运行真实问题提取，不能推断线上提取附带英文keywords后仍必然漏检。原始日志中的低分、现在的高分及v5/v6条件mock应分别理解，不混作同一输入和同一知识版本。

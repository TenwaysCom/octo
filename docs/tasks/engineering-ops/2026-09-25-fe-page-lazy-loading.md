# FE 页面懒加载与资源加载失败恢复

## 目标

将业务页面从首屏静态依赖中移出，减少登录页和 Lark 小窗加载量，消除 500 kB 构建告警，并处理异步页面加载失败。

## 验收标准

- [x] FE check 通过，所有 JS chunk 小于默认 500 kB 告警线，记录优化前后体积。
- [x] 未登录不加载业务页面；直接进入 Lark 小窗不加载平台列表、Sprint、设置模块。
- [x] 页面切换、详情直达、前进后退、筛选恢复和权限跳转正常（合成数据浏览器验证）。
- [x] 延迟加载有提示，失败可刷新恢复，切换路由重置错误状态，小窗样式正常加载。

## 背景与范围

基线：Vite 8.2.0 构建产出单一 JS 508.18 kB（gzip 148.04 kB），CSS 138.58 kB（gzip 21.95 kB）。工作树开始时干净。
仅 FE 页面加载方式；不改 API、认证、依赖、业务组件内部结构或全局 CSS，不部署。

## 方案与决策

- App 模块顶层声明 lazy，具名导出映射为 default；按原页面模块拆包，列表及 Sprint 分别保持共用模块。
- 页面外设置 Suspense 和以当前 hash 为 key 的错误边界，App 中状态及 Provider/客服浮窗生命周期保持原位置。
- 复用会话加载样式，区分会话恢复和页面加载文案。失败仅显示安全提示，用户点击刷新保留 URL；不自动刷新，避免刷新循环。
- 保留 Vite 默认拆包和告警阈值，不新增依赖。

### 构建与首屏体积

| 对象 | 优化前 JS / gzip（kB） | 优化后 JS / gzip（kB） |
| --- | --- | --- |
| 入口 / 未登录首屏 | 508.18 / 148.04 | 261.80 / 82.79 |
| Lark 小窗首屏及公共依赖 | 508.18 / 148.04 | 293.31 / 约 94.67 |
| 全部 JS 产物总计 | 508.18 / 148.04 | 约 514.59 / 160.04 |

gzip 采用 Vite 构建输出口径；首屏依赖集合来自生产构建浏览器请求，Lark 小窗 gzip 为各加载包之和，并非真实服务器压缩传输测量。临时浏览器脚本另用 Node gzip 计算，其压缩器口径与 Vite 不同，不混用。
拆包降低按页加载量，全部产物因模块边界等开销略增。最大 JS chunk 为入口 261.80 kB，平台列表为 110.24 kB。
小窗 CSS 独立为 9.84 kB（gzip 2.37 kB）；基础 CSS 为 128.73 kB（gzip 20.27 kB）。

### 浏览器验收场景（已执行）

1. 未登录直接打开 Lark 小窗：显示登录按钮，仅请求入口 JS，无业务页面 chunk。
2. 已登录直接打开小窗：显示 Ticket 搜索页，只加载小窗及公共依赖和独立 CSS，未请求列表、Sprint、设置、详情页模块；360px 无横向溢出。
3. 延迟快捷键页面 JS 响应：先显示页面加载提示，放行后显示快捷键页面。
4. 中断快捷键 JS 请求：显示失败提示；切换设置页能正常显示，后退仍保留失败提示；恢复网络并点击刷新后页面正常，hash 不丢失。
5. 无列表权限直接进入详情：跳转设置页，未请求详情页面 chunk。
6. 使用合成 Ticket 直达详情，再打开列表填写搜索条件，切换 Sprint 并前进后退后搜索条件保留；逐一验证 Sprint 详情、Meegle/GitHub 列表、同步、设置、快捷键页面渲染，无非预期页面异常。

# Lark 工单数据未变化时跳过写入

## 目标

先实现 Base 到 Octo 的重复快照不产生实际 UPDATE，再实现 Done 表情任务。保留源端增量查询及水位计算，工单未变化时不刷新同步时间、不改写 Octo AI 结果；需要修复的清洗字段仍可重试。

## 验收标准

- [x] 单条、批量及增量共用的持久化逻辑对相同源版本、字段、标题和状态跳过实际更新，字段 JSON 的键顺序不构成变化。
- [x] 源数据变化、stale 恢复、共享链接变化仍正确更新，不覆盖本地 AI。
- [x] 已一致的清洗投影不再发起清洗写入，先前失败的清洗仍可恢复。
- [x] 本地相关测试与构建通过，不执行真实批量平台测试。

## 背景与范围

自动创建会同步新记录并在标题回写后再次同步。周期增量有五分钟重叠，仍可能读到同一源版本。本次限制实际数据库写入，不承诺完全免除远端增量读取和数据库冲突检查。

## 方案与决策

在 PostgreSQL UPSERT 冲突更新增加源字段与版本比较，更新条件由数据库原子判断。清洗前比较现存派生字段与预期投影，只写需要修正的记录，避免源写入成功但清洗失败后永远跳过修复。

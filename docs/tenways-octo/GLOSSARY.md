# Octo 领域术语

Octo 连接 IT 支持、研发执行和交付。对象关系、数据归属及代码入口见[领域索引](README.md)。

## 身份与授权

### Octo 用户

Octo 内部的账号。登录时按 Lark 租户与用户身份识别，可关联 Meegle 身份和 GitHub 账号。

### Web Session

浏览器在 Octo 工作台的登录会话。打开工作台、执行 Octo 操作和访问外部平台各有对应的权限或授权检查。

### 平台授权

Octo 代表指定用户或应用访问外部平台的授权。已登录的 Octo 用户可能仍需完成或更新平台授权。

## 工单与研发

### Lark 话题

由一条群根消息及其回复组成的讨论。一条消息、一个话题和一张 Ticket 各有自己的标识。

### Lark Ticket

Lark Base 中用于登记 IT 请求和处理结果的记录，可通过消息链接关联讨论。票号用于展示和搜索，工单身份由 Base、数据表与记录共同确定。

### Meegle 工作项

Meegle 项目中可分派和跟踪的研发事项，例如 Story、Bug 或 Tech Task。每项由项目、工作项类型和工作项 ID 共同确定，可包含多个工作流节点。

### Meegle Sprint 归属

一个工作项连续归属于某个 Sprint 的时间段。同一工作项可以先后有多段归属，历史归属可能来自增量观察或存量推定。

### GitHub PR

GitHub 仓库中用于审阅和合并变更的 Pull Request。PR 编号属于所在仓库，一个工作项可以关联多个 PR。

### Odoo.sh Build

Odoo.sh 环境中的构建记录。Octo 可以按 PR 的源分支展示对应构建，PR 合并状态和构建结果分别由 GitHub 与 Odoo.sh 提供。

## 同步与数据

### 平台快照

Octo 上次成功读取的外部对象及其当前本地投影。列表和搜索可以使用该副本，源端变更在后续同步后才会反映。

### 同步范围

一次同步覆盖的配置目标，例如一个 Lark 数据表、一个 Meegle 项目下的工作项类型或一个 GitHub 仓库。增量进度按范围独立跟踪。

### 线程快照

Octo 保存的 Ticket 关联话题消息副本，带有版本、同步时间和完整性信息。它与 Ticket 的 Base 字段快照分别更新。

### 标记删除 Octo Ticket

把一张 Ticket 从 Octo 的普通列表和搜索中隐藏，保留本地历史和 Lark 原记录。

## 工单分析与知识

### 正式 Ticket AI

Octo 保存并展示在 Ticket 详情中的正式分析结果。它有独立的写入流程，可由受授权的 Support-QA 工作流更新。

### Shadow AI

后台生成并独立保存的工单分析。它使用当前工单材料，可引用 Wiki 或历史 KCS 辅助判断，供对照和评测。

### Eval 样本与 Badcase

Eval 样本固化当时的工单分析输出供评测。Badcase 是带失败标签和原因的人工标注，归属对应的样本版本。

### Wiki 问答

在选定的本票材料和检索到的知识证据上生成一次问答结果。历史案例提供适用条件和排查线索，本票事实由当前证据支撑。

### ACP 会话

用户与 Kimi 或 Hermes Agent 的可续聊会话。Ticket 会话关联对应工单，新会话采用启动时取得的线程快照，后续轮次沿用该会话的材料。

### 待确认写回草稿

受控 Support-QA 动作提出的待确认变更，例如答案反馈或正式分析更新。用户确认后由 Octo 执行对应写入。

### KCS 工单文档

从某张已结束的工单提炼的带来源历史资料，可记录处理结果、验证、适用情况和仍需核对的事项。它可以为后续工单提供参考。

### llm-wiki 知识页

可跨工单复用的知识条目，保存适用条件及指向原始证据或规则的引用。一页可以汇总多个工单的经验，也可以引用现有业务文档。

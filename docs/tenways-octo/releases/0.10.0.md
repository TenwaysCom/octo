## 1. Ticket AI：后台分析与有来源的知识问答

- **新增后台影子分析。** 对满足静默时间条件的 Ticket 更新聊天快照，自动生成问题总结与结构化分析；影子结果独立保存，不自动覆盖正式 AI 结果或进入人工评估集。
- **新增 wiki 问答入口。** 从当前 Ticket 提取问题，检索并筛选最多三篇相关知识页，结合聊天快照生成带来源编号的回复草稿；保留草稿、历史参考和适用条件提示，供用户审核。
- **统一问题总结的模型配置。** 手动 Quick Action 与后台分析共用 provider、model 和超时设置，支持 DeepSeek 与 ZCode／智谱。
- **整合正式与影子分析展示。** Ticket AI 卡片、AI 输出列表支持摘要、悬浮明细和完整详情，明确区分正式结果与影子结果，并展示处理耗时、失败原因及质量信息。
- **优化评估视图。** 更清晰地呈现 Draft、Badcase、Eval 状态、人工意图与期望结果，集中次级操作入口。

依据：[影子分析](../../tasks/ai-ticket/2026-09-03-shadow-summary-worker.md)、[wiki 问答](../../tasks/ai-ticket/2026-09-11-wiki-qa-quick-action.md)、[共享模型配置](../../tasks/ai-ticket/2026-09-05-shared-zcode-ticket-summary-provider.md)、[Ticket AI 整合](../../tasks/ai-ticket/2026-09-12-ticket-ai-shadow-integration.md)、[AI 与评估展示](../../tasks/ai-ticket/2026-09-06-shadow-ai-fe-details.md)。

## 2. AI 会话：关闭面板后继续执行，审批状态更清楚

- **接入 Hermes 原生 ACP。** 支持 provider 与原生会话标识保存、历史恢复，以及 Ticket／Sprint 业务会话。
- **生成过程与面板解耦。** 收起面板、切页或短暂断连后，服务端继续当前运行；重新打开可恢复内容和运行状态，另设“停止生成”操作。
- **完善审批交互。** 显示申请操作、命令参数、文件修改差异和倒计时；支持允许、拒绝及重开后的审批状态恢复，避免重复提交。
- **改善失败与历史呈现。** 保留轮次和工具步骤边界，避免将空结果、审批拒绝或晚到的完成事件显示为成功；普通会话失败后可继续处理。
- **Support-QA 材料迁移至 llm-wiki。** 加强当前 Ticket 证据绑定及文件编辑核对，保留业务发布确认与写后读取验证。

依据：[Hermes 接入](../../tasks/acp/2026-09-05-hermes-acp-integration.md)、[会话生命周期](../../tasks/acp/2026-09-06-fe-ai-session-lifecycle-discussion.md)、[审批交互](../../tasks/acp/2026-09-10-fe-hermes-permission-approval.md)。

## 3. Lark Ticket：直接编辑属性与快捷操作

- **列表右键菜单。** 在列表、分组和看板中直接修改状态、负责人、需求人、紧急度、类型、Business Line，并支持创建关联 Meegle 工作项。
- **详情页属性编辑。** 六类属性支持可搜索的选项浮层、键盘操作和点选保存；保存成功后同步更新详情及前后导航缓存。
- **写入结果更明确。** 写回 Lark Base 后重同步本地数据；区分写入失败与“Lark 已写入、Octo 同步失败”，并防止重复提交、重复建单。
- **补齐信息与导航。** 完善业务线、创建／关闭时间和解决方案展示，支持沿当前列表上下文切换上一条／下一条 Ticket，优化标签配色与资源入口。

依据：[右键操作](../../tasks/platform-data/2026-09-11-lark-ticket-context-menu-actions.md)、[属性编辑](../../tasks/platform-data/2026-09-11-lark-ticket-detail-field-editing.md)、[详情导航](../../tasks/platform-data/2026-09-06-lark-ticket-detail-navigation.md)、[字段展示](../../tasks/ai-ticket/2026-09-11-lark-ticket-field-display-audit.md)。

## 4. Meegle 与 Sprint：进入分类、历史补齐和列表优化

- **补齐 Sprint 进入分类。** 展示“结转、按期排入、中途加入、证据不足”，提供结转来源；基于推定时间的分类带“推定”标识。
- **补齐历史归属初始化。** 从本地 PostgreSQL 现有证据生成缺失的当前归属，默认预览、显式执行写入，支持重复执行；与增量同步共享行锁，避免竞争插入和过期候选写入。
- **更易查看 Sprint 进度。** 筛选标签展示状态、完成数和完成率；结转工作项优先分区，优化图表、时间列、当前相关人和类型徽标。
- **精简关联 PR 展示。** 压缩 PR 与构建状态徽标；已关联 PR 少于三个时保留补加入口。
- **改善大列表浏览。** 调整平台列表数量上限，优化默认类型分组及 Ticket／GitHub PR 分组折叠行为。

Sprint 历史与归属区间在此前版本已有基础能力；本版重点是补齐分类、初始化及展示，不能恢复快照中早已丢失的旧 Sprint 关系。

依据：[Sprint 历史](../../tasks/platform-data/2026-08-27-meegle-sprint-history.md)、[筛选进度](../../tasks/platform-data/2026-09-03-meegle-sprint-filter-summaries.md)、[关联 PR](../../tasks/platform-data/2026-09-12-meegle-list-pr-compact-and-add-entry.md)、[列表上限](../../tasks/platform-data/2026-09-06-platform-list-page-size.md)。

## 5. Odoo.sh：构建同步与失败通知

- **新增后台定时刷新。** Server 启动时刷新 EU、UK、US 三个环境，之后每 30 分钟刷新一次，不依赖页面访问。
- **持久化构建历史。** 首次初始化只保存历史、不补发历史失败通知；之后对新增失败或从非失败转为失败的构建入队通知。
- **新增 Lark 群通知能力。** 消息包含环境、分支、构建及 commit 链接；可通过明确维护的作者映射和用户绑定 @ 对应人员，未知身份仍可发送正文。
- **控制重复通知。** 使用持久化通知状态和幂等键；明确可重试的错误进行有限重试，发送结果不确定时停止自动重发，等待核实。
- **优化页面构建状态。** 调整状态图标、缓存刷新与错误呈现。

**验证边界：** 定时刷新与本地历史初始化已有运行记录；真实 Lark 成功送达仍未验收。台账中最近一次发送因机器人未加入目标群而失败，需完成群权限配置后验证。后台刷新依赖 Server 进程运行，未提供跨实例调度锁。依据：[Odoo.sh 构建通知](../../tasks/engineering-ops/2026-09-10-odoo-build-failure-lark-notification.md)。

- 完善模型超时、输出格式、证据越界及 provider 错误诊断，记录影子分析耗时，避免单条失败阻塞后续处理。
